# README OCR 完整流程说明设计

日期：2026-07-28

## 目标

扩展仓库根目录 `README.md` 的 OCR 章节，使第一次打开仓库的开发人员和业务人员能够直接理解：

1. 审计报告 PDF 如何进入资产评估工作流；
2. OCR 缓存、阿里云文档解析和本地 PaddleOCR 的选择关系；
3. `OCR结构化结果.xlsx` 与用户上传的两类业务 Excel 的区别；
4. OCR 结果如何通过语义规则匹配字段并传递来源证据；
5. 缺失、冲突和云端失败时 Word 与问题清单如何处理。

本次只修改说明文档，不改变代码、配置、Prompt 或运行行为。

## README 结构

OCR 章节按以下顺序组织：

1. **OCR 在完整资产评估工作流中的位置**
   - 明确 OCR 只负责把审计 PDF 转换成可匹配的结构化证据；
   - OCR 不直接决定 Word 应填什么，也不替代业务 Excel、企查查或百炼。

2. **端到端流程图**
   - 前端上传 PDF；
   - SHA-256 缓存判断；
   - 缓存命中时复用已有 OCR 工作簿；
   - 缓存未命中时调用阿里云文档智能；
   - 归一化页、文本块、表格和单元格；
   - 导出 OCR 工作簿；
   - 按科目、期间、单位和表头执行语义匹配；
   - 按黄色字段来源白名单合并；
   - 填充 Word、保留未解决占位符并生成审计产物。

3. **逐步说明**
   - 输入与跳过条件；
   - 缓存键和强制重跑行为；
   - 阿里云异步提交、轮询和分页结果获取；
   - 统一 OCR 数据契约；
   - OCR 工作簿的工作表和用途；
   - 字段匹配和来源证据传递；
   - Word 填充与问题清单。

4. **三类 Excel 的边界**
   - `OCR结构化结果.xlsx`：系统根据 PDF 自动生成或复用，不由用户上传；
   - 资产基础法/资产清查 Excel：用户可选上传的业务工作簿；
   - 收益法或市场法 Excel：用户可选上传的估值工作簿；
   - 三者可以共同提供候选数据，但黄色字段只能采用配置允许的指定来源。

5. **配置、失败与安全策略**
   - 默认阿里云，PaddleOCR 只在显式配置时加载；
   - 未上传 PDF、凭证缺失、超时、额度不足或解析失败均不阻止待复核 Word；
   - 缺失保留黄色 `XXX`，冲突不猜测，写入带页码问题清单；
   - AccessKey 只通过 `.env` 或宿主环境注入；
   - RAM 权限优先使用官方文档中的系统策略；控制台不可用时可创建仅限 `docmind:*` 的自定义策略。

## 与完整资产评估工作流的关系

README 在 OCR 章节后明确总结当前工作流：

```text
人工输入
  + 审计 PDF → OCR结构化结果.xlsx
  + 资产基础法/资产清查 Excel
  + 收益法或市场法 Excel
  + 企查查 API
  + 百炼叙述
→ 字段来源白名单与语义映射
→ 固定 Word 模板填充
→ 格式审核、数据校验、语义审核
→ 待复核报告、字段审计清单、带页码问题清单
```

这就是项目最初定义的资产评估报告生成业务内核；用户、权限、并发、持久化、监控和发布仍由 c2m 等生产外壳负责。

## 验收标准

1. README 能独立解释 OCR 从 PDF 到 Word 的完整路径；
2. 不再让用户误以为 `OCR结构化结果.xlsx` 需要上传；
3. 不再让用户误以为 OCR 会读取或替代收益法、市场法工作簿；
4. 明确缓存命中、未上传 PDF 和云端失败三种分支；
5. 明确缺失留黄、冲突不猜和来源证据进入审计清单；
6. 所有描述与当前 `demo/workflow.yaml`、`demo/pipeline.py` 和前端三个上传项一致；
7. 不包含任何真实 AccessKey、客户文件名或运行产物。
