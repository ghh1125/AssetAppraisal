# 资产评估 Demo 工作流契约化改造设计

## 1. 目标

在不重写现有 OCR、Excel 解析、企查查查询和 Word 填充规则的前提下，把新增的人工输入、主体概况模块选择、叙述生成和三类 LLM 审核改造成可独立验证、可审计、可由 c2m 接入的业务资产。

本次改造完成后，每次运行都应能回答：

- 工作流实际执行了哪些节点；
- 每个节点接收什么输入、产生什么输出；
- 每个字段来自人工输入、PDF/OCR、Excel、企查查还是 LLM；
- 使用了哪个规则版本、Prompt 版本、数据版本和模型；
- 哪个节点失败、降级或需要人工确认；
- 新增业务规则是否有正常样例和边界样例覆盖。

## 2. 范围

### 2.1 本次包含

- 人工输入校验；
- 主体概况模块选择；
- PDF/OCR、Excel、企查查、LLM 字段合并后的来源追踪；
- 评估报告 Word 生成；
- LLM 格式审核、数据校验、语义审核；
- 审核汇总及最终候选报告；
- 工作流节点契约校验；
- 运行轨迹、版本和问题清单输出；
- 至少 10 个代表性验收样例。

### 2.2 本次不包含

- 重写 PaddleOCR 或 Excel 解析算法；
- 把 Demo 改造成生产级异步任务系统；
- 用户、权限、数据库、对象存储、重试、监控和发布系统；
- 自动接受 LLM 修改并覆盖正式报告；
- 把 Demo 仓库作为 c2m 的运行时依赖。

## 3. 方案选择

采用“契约化改造”方案：

- `domain/` 保存可移植的纯业务规则；
- `adapters/` 负责 Word、Excel、OCR、企查查和 LLM 等外部能力；
- `pipeline.py` 只负责编排；
- `schemas.py` 定义节点输入输出；
- `workflow.yaml` 定义节点顺序和人工检查点；
- 每次运行生成结构化轨迹，供 c2m 读取或转换。

不引入新的通用工作流引擎，避免在 Demo 阶段扩大范围。

## 4. 组件设计

### 4.1 节点契约注册表

新增纯业务模块 `demo/domain/workflow_contracts.py`，负责：

- 从 `workflow.yaml` 读取节点声明；
- 校验每个节点的输入模型和输出模型是否存在；
- 校验字段是否有中文说明、示例和必填标识；
- 校验依赖节点是否存在且无环；
- 校验人工检查点是否为明确文字；
- 返回可 JSON 序列化的校验结果。

该模块不读取环境变量，不调用文件、网络、数据库或 UI。文件内容由调用方传入。

### 4.2 运行轨迹

新增纯业务模型：

- `WorkflowTrace`
- `NodeTrace`
- `ArtifactRecord`
- `VersionRecord`

每个节点记录：

- 节点名称；
- 状态：`completed`、`completed_with_issues`、`skipped`、`failed`；
- 开始和结束时间；
- 输入模型、输出模型；
- 经过 Pydantic 校验的输入摘要和输出摘要；
- 规则、Prompt、模型和数据版本；
- 来源证据；
- 问题列表；
- 是否需要人工确认。

轨迹写入由适配器完成，业务模型只返回普通字典。

### 4.3 节点执行边界

新增轻量执行辅助模块 `demo/adapters/workflow_trace.py`：

- 接收节点名称、输入模型、输出模型和节点函数；
- 执行前校验输入；
- 执行后校验输出；
- 捕获结构校验错误并写入问题；
- 将节点轨迹追加到内存；
- 最终写出 `workflow_trace.json`。

原有 OCR、Excel、企查查、LLM 和 Word 适配器不迁移、不重写。

### 4.4 新增规则下沉

把当前散落在编排层中的下列判断整理为纯函数：

- 主体概况模块白名单过滤；
- LLM 字段是否允许生成；
- 审核节点状态归一化；
- 最终候选报告是否允许生成；
- 人工输入缺失时的业务处置。

纯函数只接收普通 Python/Pydantic 数据，并返回可 JSON 序列化结果。

### 4.5 配置与版本

更新 `data_manifest.yaml`：

- 增加工作流契约版本；
- 增加三类审核输出结构版本；
- 增加主体概况模块规则版本；
- 明确每项来源缺失时的业务处理。

更新 `workflow.yaml`：

- 保持现有节点顺序；
- 为每个节点保留输入模型、输出模型、依赖和人工检查点；
- 增加工作流契约版本，不写项目绝对路径。

## 5. 数据流

1. 前端提交人工输入和五类材料。
2. 运行外壳读取配置、工作流定义和数据清单。
3. 契约注册表在正式执行前完成静态校验。
4. PDF 命中缓存时读取已有 OCR 结果；未命中时执行 OCR。
5. OCR 结果归一化并输出结构化 Excel。
6. PDF/OCR、三类 Excel、人工输入和企查查分别产生带证据的候选字段。
7. 业务规则按黄色字段来源白名单解析最终字段。
8. 用户选择的主体概况模块进入 LLM 生成节点，未选择模块对应的黄色提示被清空且不生成内容。
9. 复制只读模板并生成待复核 Word。
10. 三类审核分别读取待复核 Word 和结构化证据；执行顺序不影响各自输出契约。
11. 审核结果汇总，生成问题清单和最终候选 Word。
12. 输出字段审计、运行清单、工作流轨迹和全部产物下载信息。

## 6. 错误与降级规则

- 工作流契约不合法：运行前终止，不生成报告。
- 模板、PDF 或必需财务字段缺失：终止生成并给出明确字段和来源。
- 企查查不可用：相关字段留空，记录问题，其他节点继续。
- LLM 叙述生成不可用：相关黄色字段留空，记录问题，其他节点继续。
- 单个 LLM 审核失败：保留待复核报告，其他审核继续，汇总状态标为存在问题。
- OCR 已有缓存：直接复用，不重复执行 OCR。
- 非白名单来源返回字段：丢弃并记录越权问题。
- LLM 审核建议不自动写回正式报告；最终候选报告仍需评估师确认。

## 7. 输出产物

每次运行至少输出：

- `资产评估报告_待复核.docx`
- `资产评估报告_最终候选.docx`
- `OCR结构化结果.xlsx`
- `字段审计清单.xlsx`
- `issues.json`
- `run_manifest.json`
- `workflow_trace.json`
- `格式审核.json`
- `数据校验.json`
- `语义审核.json`
- `审核汇总.json`

所有输出写入新的时间命名运行目录，不覆盖输入模板和上传材料。

## 8. 验收样例

新增不少于 10 个脱敏样例，至少覆盖：

1. 三种评估方法正常组合；
2. 未选择任何评估方法；
3. 六个主体概况模块全部选择；
4. 只选择一个主体概况模块；
5. 主体概况模块为空；
6. 企查查返回其他公司数据；
7. LLM 返回越权字段；
8. 单个 LLM 审核失败；
9. 必需财务字段缺失；
10. OCR 缓存命中；
11. Prompt 或模型按节点覆盖；
12. 工作流声明引用不存在的模型。

对非确定性 LLM 输出只校验结构、必备字段、来源边界和业务约束，不断言全文。

## 9. 自动检查

新增测试确保：

- `workflow.yaml` 中所有模型都能在 `schemas.py` 找到；
- 每个模型字段都有中文说明、示例和必填标识；
- 工作流依赖合法且无环；
- 每个关键规则同时存在正常与边界样例；
- Prompt 文件和输出 JSON Schema 均带版本并已登记；
- `domain/` 不导入 FastAPI、Vue、Streamlit、数据库模型或外部客户端；
- 运行完成后 `workflow_trace.json` 覆盖实际执行节点；
- 轨迹、审计清单和运行清单中的版本与证据一致。

## 10. c2m 交接边界

c2m 只需要调用工作流入口并消费结构化产物，不直接依赖 Demo 页面状态。未来生产接入由 c2m 负责：

- 用户和权限；
- 任务持久化；
- 并发和异步；
- 上传隔离与对象存储；
- 超时、重试、幂等和限流；
- 监控、日志、错误码和恢复；
- 正式发布与回归流程。

Demo 提供的是业务规则、节点契约、Prompt、样例、证据和结构化输出，不承担生产外壳职责。
