# CHANGELOG

- “3、被评估单位概述”下由模型生成并经用户选择写入的内容，改为共享一个章节级来源批注；各段仍保留状态底色，不再为六个候选模块重复添加相同批注。

## Unreleased

- Word 表格批注改为真正覆盖整张表的选择范围：全表正常时仅保留一条整表核验批注；部分异常时整表概览说明通过、待复核和缺失数量，异常单元格另附具体批注，正常单元格不再重复堆批注；各单元格状态底色保持不变。
- 修复 LLM 未返回有效表级复核结论时虚构“1 项不通过”却没有异常单元格的问题：此时整表统一标红，非缺失项计入“待人工核对”，只有已确定的 PDF/Excel 差异才计为“不通过”并落到具体单元格。
- 表格审阅状态改为单元格级显示：已核验数据使用更明显的绿色、Excel 降级来源使用橙色、真实冲突使用红色、缺失值保留黄色；整表级 LLM 口径提示改挂表格说明文字，不再把整表所有数据误标红。
- 同来源、同状态的表格数据继续合并为一条综合来源批注；整表 LLM 提示直接沿用模型已生成的具体复核结论，避免二次改写丢失页码、工作表及口径说明。
- 修复网页人工选择候选后的最终填充阶段未传入 LLM 复核器的问题：最终 Word 现在会真实执行取数证据复核和来源批注撰写；只有模型返回受控的 `accept` 才显示“系统语义匹配成功，并经大模型复核通过”，调用失败、无效返回或存在歧义继续转为“数据需人工核对”，不会把规则匹配冒充为大模型审核通过。
- Word 表格来源批注改为整表聚合：同一张表中来源和审核状态相同的数据只保留一条综合批注，全部已填单元格仍分别保留状态底色；表内出现缺失、冲突或不同来源状态时才另设对应批注，避免同一出处重复几十次。
- 修复部分冲突表格被整表标记、正确数据缺少综合来源批注的问题：PDF/Excel 差异继续精确落到对应科目和期间单元格并标红，未发生差异的单元格保持绿色；表级 LLM 结论不再额外挂到无冲突的代表值，综合来源批注遇到已有异常批注时会自动选择下一个正常数据单元格。
- 增强 Word 状态底色辨识度：已核验、未完成 PDF 对照、冲突/需人工复核分别使用更清晰的浅绿、浅橙和浅红，缺失 `XXX` 继续保持亮黄底色与红字；不改变模板边框、字体和排版。
- Word 输出新增全字段可追溯标注：每个实际填入的人工字段、PDF/OCR/Excel 数值、企查查 API 内容和用户采用的百炼叙述均添加状态底色及来源批注。浅绿表示来源/匹配已通过，浅橙表示未完成 PDF 对照，浅红表示冲突或复核存疑；黄色 `XXX` 继续表示完全缺失，同时改为红字并附 `【未找到数据】` 批注。批注标题由程序固定为 `【来源已核验】`、`【来源待补充核验】`、`【数据冲突，需人工复核】` 和 `【未找到数据】`；正文新增 `traceability_comments.v1` 受限 LLM 撰写步骤，只能改写已确认的来源证据，不能改数、改来源或编造定位，失败时使用确定性正文兜底。
- Word 审核批注升级为 `word_review_comment.v2`：确定性规则先按表格、科目和期间定位 Word 中的具体金额；程序再把字段、采用值、PDF/Excel 双方文件与定位、复核状态以及真实金额候选交给 LLM。模型只复核规则位置并生成面向评估人员的中文批注，不能改数、改来源或编造位置。
- LLM 确认具体金额位置合理时正常写入其生成的批注；定位存在期间、口径或科目疑点时，仍只在规则已唯一找到的具体金额上标红并写明原因。重复金额无法唯一确认时放弃该批注，不改挂科目行名、期间表头或章节标题。同一具体金额的多个复核事项在同一批注中以“复核项 2/3…”追加，避免重叠批注损坏文档。
- LLM 取数复核新增失败关闭兜底：模型超时、返回空结果、非法状态或结构无效时，程序保留原值和来源并自动生成 `needs_review` 及人工核对批注；规则已标记多来源差异或非主来源时，不接受模型返回 `accept`。
- LLM 取数复核的 `needs_review`/`conflict` 结果现在会在对应 Word 数值旁使用浅红底色并写入 `【数据冲突，需人工复核】` 批注；`missing` 继续由黄色 `XXX` 规则处理，并附红字缺失提示。PDF 页码定位先使用 OCR 表格/文本证据，未定位项再由受限页码定位器从已有 OCR 页码中选择，用户界面不再显示“页码未定位”或内部 OCR 工作簿名称。
- 默认百炼模型更新为 `deepseek-v4-pro-0813`；请求失败时仍自动降级到 `qwen3.8-max`，也可通过环境变量或项目配置覆盖。
- 新增 `evidence_review.v1` LLM 取数复核：对每个已找到的 PDF/OCR 或 Excel 逻辑字段/表格审阅候选的科目、期间、单位、口径和定位证据，返回受控的 `accept/needs_review/conflict/missing` 结论。模型没有改数、改来源或新增字段权限；疑点只以 Word 批注提示人工复核，并保留完整 JSON 记录。
- PDF/表格差异现在进入最终 Word 的人工审核闭环：审计 PDF 来源字段仍按 PDF 值填入；若与任一表格数值不一致，该数字标红并附 Word 批注。批注包含字段、PDF/表格双方的文件和页码或工作表单元格、采用 PDF 的规则，以及基准日/口径/单位/科目定义四项复核提示。PDF 未上传或未识别到字段时，唯一语义匹配的表格值可降级填入并附“未完成 PDF 对照”批注；所有材料无值才保留黄色 `XXX`。
- 按 0817 确认版输入、模板和映射规则升级通用 Demo：审计材料改为必传且支持多份 Word/Excel/PDF；新增评估基准日，移除报告流水号；工商信息、股权结构及历史沿革、账外无形资产、企业介绍均由用户逐项选择“上传资料”或“企查查 API”。
- 新增字段级“材料整合与差异”层：所有 PDF OCR、资产基础法/资产清查工作簿、收益法工作簿先分别抽取候选并保留文件/页码或工作表/单元格证据；同值去重，不同值记录差异。审计 PDF 指定字段优先 PDF OCR；缺 PDF 或 OCR 未识别到该字段时，只允许唯一语义匹配的 Excel 以带审计提示的降级方式填入，绝不静默替代。
- 新增受控 LLM 映射代理：只允许将未分类的模板批注位置映射到现有字段白名单，不能生成数值、字段或跨来源替换；LLM 叙述仍只基于已解析的材料/API 证据生成。
- 模板切换为 `评估报告版式_0817确认.docx` 和 `评估报告版式-映射批注_0817确认.docx`；前者只读复制并填充，后者仅用于读取批注规则。
- 按 0811 复核批注修复委托类型和百分号显示：模板中的静态“拟收购”随人工选择的委托类型统一替换；增值率占位符在模板未提供百分号时自动补 `%`，已有百分号时不重复添加。
