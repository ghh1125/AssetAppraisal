# 资产评估 Word 填充映射文档设计

## 1. 目标

生成一份新的 Word 映射说明文档，完整说明《评估报告版式-沟通标注版.docx》中所有待填位置应填写什么内容、来自哪个文件或系统、如何取值以及如何核验。

本阶段不修改原评估报告，不向原评估报告填入数据。

## 2. 输入资料

1. `评估报告版式-沟通标注版.docx`
2. `通富2025.6.30合并及母公司审计报告.pdf`
3. `上报表文件_通富昆山_已处理.xlsx`
4. `通富热处理（昆山）有限公司-收益法-20250630.xlsx`

其他资料仅在确认与具体字段相关时作为辅助证据，不擅自扩大数据来源范围。

## 3. 覆盖范围

映射文档必须覆盖：

- Word 中全部 127 处 `XX`、`XXX`、`XXXX` 占位符；
- 20 个不含占位符、但黄色标注明确要求取数、生成或选择内容的位置；
- 页脚、表格以及正文中的待填位置；
- 同一业务字段在 Word 中的所有重复出现位置；
- 条件性章节，例如收益法、资产基础法及最终结论选择。

## 4. 映射文档结构

### 第一部分：数据来源说明

说明每个输入文件的用途、数据口径、期间、单位和适用字段。

### 第二部分：业务字段来源总表

按唯一业务字段归并，包含：

- 字段编号；
- 标准字段名；
- 中文名称；
- 数据类型；
- 来源类别；
- 来源文件；
- PDF 页码和表名，或 Excel 工作表和单元格/行列匹配规则；
- 取数及计算规则；
- 单位与口径；
- 是否需要人工复核；
- 缺失及冲突处理规则。

### 第三部分：计算与校验规则

包括但不限于：

- 评估增值额 = 评估值 - 账面值；
- 增值率 = 评估增值额 / 账面值；
- 报告有效期起止日期；
- 金额大小写转换；
- 资产负债表平衡关系；
- 合并口径与母公司口径区分；
- 元、万元等单位换算；
- PDF、上报表和收益法工作簿之间的交叉核验。

### 第四部分：缺失、冲突和外部数据

将无法从现有文件直接取得的字段划分为：

1. 人工输入；
2. 用户选择；
3. API 获取；
4. 大模型生成；
5. 现有资料不足，待补充。

### 附录 A：所有占位符逐项映射

逐项列出 127 处占位符，保留 Word 原文上下文，并记录其标准字段、来源和重复字段关系。

### 附录 B：黄色标注内容块逐项映射

逐项列出 20 个不含占位符的生成、取数或选择任务。

### 附录 C：重复字段与一致性关系

列出同一字段在封面、摘要、正文、评估结论及页脚等位置的复用关系，保证一次取值、多处一致填入。

## 5. 来源类别及优先级

### 审计历史数据

优先使用审计报告 PDF 的结构化表格结果，并记录原 PDF 页码、表名及口径。

### 上报及资产基础数据

优先使用 `上报表文件_通富昆山_已处理.xlsx`。若与审计报告存在差异，保留双方数值并标记冲突，不自动覆盖。

### 收益法数据

优先使用 `通富热处理（昆山）有限公司-收益法-20250630.xlsx`，包括预测期、永续期、折现率、自由现金流及收益法评估结果。

### 系统计算

派生值统一重新计算，不直接照抄显示结果。计算结果需与来源文件中的结果交叉核验。

### API 获取

对企业工商、股东、历史沿革、知识产权及类似外部信息，单独记录：

- 建议 API 类型或供应商；
- 查询主体及统一社会信用代码等关键参数；
- 所需返回字段；
- 数据时点要求；
- 接口失败后的人工补录方案；
- 是否必须由人工确认。

API 数据不得直接视为审计证据，涉及报告事实陈述时必须保留来源和查询日期。

### 大模型生成

仅用于行业介绍、业务概述、市场分析、主要产品、客户供应商概述、盈利模式、SWOT 和对标公司分析等叙述性内容。所有生成内容必须标记证据来源和人工复核要求，不允许用大模型生成财务数字。

## 6. PDF 表格处理原则

为确定 Word 字段与审计报告的准确关系，需要识别 PDF 中全部表格。每张表至少记录：

- 原 PDF 页码；
- 表名；
- 合并或母公司口径；
- 报告期；
- 单位；
- 表头层级；
- 行项目名称；
- 识别质量及人工复核状态。

若表格跨页，应合并为一个逻辑表，同时保留全部原始页码。

## 7. 映射判定规则

1. 不根据 `XXX` 的出现顺序推断字段，而根据所在段落、标题、表格及上下文判定。
2. 每个 Word 位置必须有唯一位置编号。
3. 每个映射必须能追溯到文件、页码/工作表和具体取值规则。
4. 无法确定的映射必须明确标记，不得猜测。
5. 条件性内容必须注明触发条件，例如“选择收益法时使用”。
6. 重复字段使用同一标准字段名，避免同一数据在不同位置产生不一致。

## 8. 质量检查

- 覆盖率：127 处占位符及 20 个黄色生成块均有记录；
- 来源完整性：每项均有来源或明确的待补状态；
- 口径一致性：公司主体、日期、报表层级和单位明确；
- 计算正确性：派生字段有公式及异常处理；
- 可追溯性：可定位至 PDF 页码或 Excel 工作表/单元格；
- 可实施性：后续程序可依据标准字段名和位置编号完成原位填充。

## 9. 交付物

交付一份新的 `.docx` 映射说明文档。原评估报告及所有来源文件保持不变。

映射文档以“唯一业务字段主表 + 全部位置附录”的混合形式组织，兼顾人工审阅和后续程序实现。

## 10. 本阶段不包含

- 不向原评估报告写入任何数据；
- 不修改原 Word 格式；
- 不调用付费 API；
- 不根据不完整证据生成或推断财务数字；
- 不决定最终采用收益法还是资产基础法，仅记录条件映射规则。
