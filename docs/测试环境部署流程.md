# 测试环境部署流程

本文适用于当前阿里云 ECS 测试环境：

| 项目 | 配置 |
| --- | --- |
| 代码目录 | `/root/rosella/AssetAppraisal` |
| 前端服务 | Nginx，监听 `8002` |
| 前端静态目录 | `/var/www/asset-appraisal` |
| 后端服务 | `asset-appraisal.service` |
| 后端地址 | `127.0.0.1:8012` |
| 后端入口 | `demo.api_server:app` |

测试环境更新采用“拉取代码 → 同步依赖 → 测试 → 构建前端 → 重启后端 → 发布前端 → 验收”的顺序。当前项目没有数据库迁移。

## 1. 部署前检查

### 1.1 避开正在运行的任务

后端任务状态保存在 Uvicorn 进程内。重启后端会中断正在解析、生成报告或等待人工选择的任务。部署前应停止接收新任务，并等待现有任务结束。

### 1.2 检查代码和保存回滚版本

```bash
cd /root/rosella/AssetAppraisal

git status --short
git rev-parse HEAD | sudo tee /var/tmp/asset-appraisal-before-deploy.sha
git log -1 --oneline
```

`git status --short` 应无输出。如果存在未提交改动，先确认改动来源，不要直接拉取或切换版本。

### 1.3 检查运行配置

不要覆盖仓库根目录中的 `.env`。确认文件存在且只有服务账号可读：

```bash
sudo test -r /root/rosella/AssetAppraisal/.env
sudo chmod 600 /root/rosella/AssetAppraisal/.env
```

节点 1 使用仓库内置的版本化中性模板包：

```text
demo/workbook_templates/workbook_templates.json
demo/workbook_templates/asset_base_v1.xlsx
demo/workbook_templates/income_approach_v1.xlsx
```

这些文件随 Git 一起发布，不需要在 `资产评估工作流/` 下手工放置客户模板。

### 1.4 一次性系统依赖

Python 必须为 3.11。RAR 解压需要 Ubuntu 上的 `bsdtar`：

```bash
python3.11 --version

command -v bsdtar || {
  sudo apt-get update
  sudo apt-get install -y libarchive-tools
}

bsdtar --version
```

前端依赖中的部分包要求 Node.js `22.18.0` 以上的兼容版本。执行 `npm ci` 前先检查：

```bash
node --version
npm --version
```

## 2. 更新代码

如果服务器已经拉取最新代码，只执行最后三条确认命令即可。

```bash
cd /root/rosella/AssetAppraisal

git fetch origin
git switch main
git pull --ff-only origin main

git status --short
git log -1 --oneline
git merge-base --is-ancestor d9623e2 HEAD && echo "已包含中性模板修复"
```

最后一条必须输出“已包含中性模板修复”。

## 3. 同步后端依赖并验证

```bash
cd /root/rosella/AssetAppraisal

uv sync \
  --frozen \
  --python 3.11 \
  --extra dev \
  --extra services \
  --extra web
```

验证内置模板包的文件、SHA-256、Sheet 和公式结构：

```bash
.venv/bin/python -c \
  'from demo.template_bundle import load_workbook_template_bundle; b = load_workbook_template_bundle(); print(b.version, b.asset.name, b.income.name)'
```

然后运行后端测试：

```bash
.venv/bin/python -m pytest -q
```

模板校验或测试失败时停止部署，不要重启后端。

## 4. 测试并构建前端

```bash
cd /root/rosella/AssetAppraisal/frontend

npm ci
npm test
npm run build

test -f dist/index.html
test -d dist/assets
```

不要在测试服务器上使用 `npm run dev` 对外提供服务。

## 5. 发布

后端先于新版前端生效，可以避免新版页面短暂调用旧接口。

### 5.1 重启后端

```bash
sudo systemctl restart asset-appraisal
sudo systemctl status asset-appraisal --no-pager
sudo ss -lntp | grep 8012
```

正常状态应为 `active (running)`，并且只监听 `127.0.0.1:8012`。

### 5.2 发布前端

```bash
cd /root/rosella/AssetAppraisal/frontend

sudo install -d /var/www/asset-appraisal
sudo rsync -a /root/rosella/AssetAppraisal/frontend/dist/ /var/www/asset-appraisal/
```

仅更新静态文件时不需要重启 Nginx。只有修改 Nginx 配置后才执行：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

## 6. 部署后验证

### 6.1 服务检查

```bash
curl -sS -o /dev/null -w "backend=%{http_code}\n" \
  http://127.0.0.1:8012/docs

curl -sS -o /dev/null -w "frontend=%{http_code}\n" \
  http://127.0.0.1:8002/

curl -fsS http://127.0.0.1:8012/openapi.json \
  | grep -q "/api/v1/asset-appraisal/workbook-intakes" \
  && echo "材料包预处理接口已加载"
```

前两条应返回 `200`，最后一条应输出“材料包预处理接口已加载”。

确认 Nginx 实际代理到后端 `8012`：

```bash
sudo nginx -T 2>/dev/null \
  | grep -E "listen 8002|root /var/www/asset-appraisal|proxy_pass http://127.0.0.1:8012"
```

### 6.2 日志检查

```bash
sudo journalctl -u asset-appraisal -n 100 --no-pager
sudo tail -n 100 /var/log/nginx/error.log
```

日志中不应出现模板完整性校验失败、权限不足、端口占用、RAR 解压失败或 Python 导入错误。

### 6.3 页面验收

依次完成以下检查：

1. 强制刷新浏览器，确认页面可以从 `8002` 打开。
2. 上传一个小型 ZIP，确认材料包预处理进度能够正常推进。
3. 下载并打开生成的 `资产法.xlsx` 和 `收益法.xlsx`。
4. 使用一份 RAR 验证 `bsdtar` 解压链路。
5. 将预处理结果接入后续流程，完成候选选择并下载 `资产评估报告_待复核.docx`。
6. 再使用直接上传 PDF/Excel 的旧入口跑一次，确认原流程没有回归。

## 7. systemd 配置基线

日常发布不需要修改 systemd。需要排查服务配置时执行：

```bash
sudo systemctl cat asset-appraisal
```

当前关键配置应等价于：

```ini
[Service]
Type=simple
User=root
Group=root
WorkingDirectory=/root/rosella/AssetAppraisal
Environment="PYTHONUNBUFFERED=1"
EnvironmentFile=-/root/rosella/AssetAppraisal/.env
ExecStart=/root/rosella/AssetAppraisal/.venv/bin/python -m uvicorn demo.api_server:app --host 127.0.0.1 --port 8012
Restart=on-failure
RestartSec=5
TimeoutStopSec=30
```

不要增加多个 Uvicorn worker。当前任务状态保存在进程内，多 worker 会使任务创建和状态查询可能落在不同进程。

如果修改了 unit 文件，需要执行：

```bash
sudo systemctl daemon-reload
sudo systemctl restart asset-appraisal
```

## 8. 回滚

只有部署前 `git status --short` 为空时，才使用下面的 Git 回滚流程：

```bash
cd /root/rosella/AssetAppraisal

git switch --detach "$(cat /var/tmp/asset-appraisal-before-deploy.sha)"

uv sync \
  --frozen \
  --python 3.11 \
  --extra services \
  --extra web

cd frontend
npm ci
npm run build
sudo rsync -a /root/rosella/AssetAppraisal/frontend/dist/ /var/www/asset-appraisal/

sudo systemctl restart asset-appraisal
sudo systemctl status asset-appraisal --no-pager
```

回滚不会删除 `.env`、`runs/` 或 `outputs/`。当前版本没有数据库迁移，因此不需要执行数据库回滚。故障处理完成后，应切回 `main` 并通过正常发布流程部署修复版本，避免长期运行在 detached HEAD。

## 9. 常用诊断命令

```bash
# 后端实时日志
sudo journalctl -u asset-appraisal -f

# 服务重启次数和结果
sudo systemctl show asset-appraisal -p NRestarts -p Result

# 检查 8012 端口
sudo ss -lntp | grep 8012

# 检查 Nginx 错误
sudo tail -f /var/log/nginx/error.log

# 检查是否发生 OOM
sudo journalctl -k --since "30 minutes ago" --no-pager \
  | grep -Ei "out of memory|oom|killed process"
```
